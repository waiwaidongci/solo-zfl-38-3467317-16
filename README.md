# 绳结成型与滑移验收

古船模型帆索的绳结成型登记、加载循环滑移记录与验收定案系统（零运行时依赖，Node 内置 http）。

## 运行

```bash
npm start                 # http://localhost:3038
PORT=4000 npm start       # 自定义端口
DB_PATH=/tmp/k.json npm start
```

数据以原子写（临时文件 + rename）保存在 `data/knot-acceptance.json`，重启后仍在。
写临时文件或改名任一步失败，都会清掉**本次**临时文件、原库字节不变、内存回滚；
启动时只按本库文件名前缀清理遗留临时文件，不碰同目录其他数据库。
持久化失败时客户端只收到稳定错误码（`persist_failed`，`reason` 为
`write_failed`/`rename_failed`）与简短中文说明，绝对路径与系统错误仅写服务端日志。

## 验收规则（lib/knots.js）

每根索登记：索号、使用部位、**绳径 d、结型、绕圈数、尾长、预紧力、额定载荷**、成型员、验收员。

- 内置结型库给出**结型效率**（0.60~0.75）、最少绕圈数与最小尾长倍数：
  **最小尾长 = max(结型倍数 × d, 50mm)**；**最大允许滑移 = 1d**。
- 至少 **5 次加载循环**，逐次记录载荷与尾端累计滑移；循环序号服务端递增分配，
  重复、跳号、缺号一律 409 拒绝，累计滑移必须单调不减。
- 判定三档（任一拒绝项命中即拒绝，否则任一返工项命中即返工，全部合格才安全）：
  - **拒绝**：尾长缺口超过 1d / 循环不足 5 次 / 累计滑移超 1d / 滑移未稳定
    （末次增量 > 0.15d，或后三循环增量回弹超 0.3d）/ 载荷余量 < 1.25
    （结承载 = 额定载荷 × 结型效率，余量 = 结承载 / 最大试验载荷）/ 登记数据无效
    （含成型员与验收员同人）。拒绝时逐条列明原因。
  - **返工**：尾长缺口 ≤ 1d、绕圈数不足、余量在 1.25~1.5 之间。
  - **安全**：全部指标合格（余量 ≥ 1.5）。
- 页面与结果中给出**最小尾长**与**最大允许滑移**。

## 职责分离与不可覆盖

- 成型员只负责登记；验收必须由登记时指定的另一名验收员**签名确认**（签名不符 403）。
- 一次确认只生成一个不可变结果：重复确认返回 409 与原结果；确认后绳索冻结，不能再录循环。
- 并发确认 / 并发登记同一索号 / 并发录入同序号：按绳索串行化，**只成功一次**。
- 批量确认：先校验整批（不存在、已定案、签名不符），任一不满足则**整批回滚不留半批**；
  写盘失败同样回滚内存与磁盘。

页面显示统计、循环进度条、滑移趋势图（含允许上限红线）、危险项面板与定案封条。

## 测试

```bash
npm test                  # 63 个 node:test：判定/并发/回滚/持久化/严格入参/编号冲突/原子写/畸形输入/配置
npm run test:browser      # Playwright 真实浏览器走查（7 项）
```

`npm test` 用显式文件列表（`node --test tests/*.test.mjs`，由 shell 展开），
兼容 Node 20 与把目录位置参数当作模块的新版 Node。

写接口严格按 JSON 类型校验：请求体必须是对象；已知字段缺失、`null`、布尔、数组、
对象、非有限数或可强转的字符串（如 `"10"`）一律 **400** 明确报错，不做布尔→数字、
数组→字符串之类的隐式转换；未知字段同样拒绝。任何校验失败都发生在加锁与变更之前，
登记、循环、定案与磁盘内容保持不变。类型正确但验收员不符才返回 403。

畸形路径与请求体上限：路径段百分号编码非法（如 `%ff`、`%zz`、`%`）返回
**400 `malformed_path`**（读取、循环、定案、按索号查询均不返回 500）；写接口因此
不会改动任何数据。请求体有字节上限：默认 1MiB，可用环境变量 `KNOT_MAX_BODY_BYTES`
（非负整数字符串，如 `524288`）或 `createApp({ maxBodyBytes })`（非负安全整数）覆盖，
**仅在两者都未设置时才用默认值**；配置为非数字、小数、负数、带空格或超出安全整数
范围时，启动即抛 `ConfigError`（CLI 以非零码退出并打印原因），绝不静默退化为无上限。
一旦达到上限——无论 `Content-Length` 已声明超限（停滞、永不发送的客户端）还是分块
传输流式累计超限（巨大/无限流）——都**立即停止接收、不再排空上游**，在 JSON 解析前
返回 **413 `payload_too_large`**，响应带 `Connection: close` 并在 flush 后结束连接
（停滞或无限流不会长期占用连接）；上限为 0 时任何有字节的请求体都 413、空体仍正常
进入校验。超限请求不写入、不锁定，服务继续可用。错误响应只含稳定错误码与简短说明，
不泄露内部路径。

浏览器走查覆盖：安全 / 返工 / 拒绝（危险项列明原因）/ 8 并发确认只成功一次 /
批量回滚不留半批 / 服务重启后刷新仍在且不可重复确认 / 全程无页面 JS 错误，
截图输出到 `tests/screenshots/`。

## API

写接口（循环 / 定案 / 批量）路径参数一律使用服务端生成的**内部编号 `id`** 精确定位，
绝不回退到自定义索号：若路径值是某根索的索号，返回 **400 `use_internal_id`**
（未知编号则 404），避免“索号恰等于另一根索内部编号”时写错对象。
登记时若新索号等于任何已有内部编号，返回 **409 `rope_no_matches_internal_id`**。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/knots` | 结型库与限值 |
| GET | `/api/ropes` | 绳索列表（含实时判定预览） |
| GET | `/api/ropes/:id` | 按**内部编号**精确读取（是索号时返回 400 指引） |
| GET | `/api/ropes/by-rope-no/:ropeNo` | 明确按**索号**查询 |
| POST | `/api/ropes` | 成型登记（索号重复 / 占用内部编号均 409） |
| POST | `/api/ropes/:id/cycles` | 按内部编号追加循环（body 须带 `expectedSeq`） |
| POST | `/api/ropes/:id/confirm` | 按内部编号，验收员签名定案（不可覆盖） |
| POST | `/api/ropes/batch-confirm` | `ids` 必须全部是内部编号；非法编号 400，状态冲突 409 整批回滚 |
